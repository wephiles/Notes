# 1. 什么是 Agent？怎么使用 Agent？

### 1.1 本质理解

**Agent 不是一种具体的技术，而是一种“让模型能做事”的架构模式。**

普通 LLM 用法：你问一句，它答一句，没有外部动作。
Agent 用法：你给一个目标，它会自己规划步骤、调用工具、观察结果、修正行动，直到完成目标。

一个最小 Agent 的循环：

```
用户目标 → 模型思考 → 决定调用哪个工具 → 执行工具 → 拿到结果 → 再思考 → ... → 最终回答
```

在代码层面，Agent 的核心就是：

```
while not task_completed:
    thought = model.reason(messages, tools)
    if thought.wants_to_call_tool:
        result = call_tool(thought.tool_name, thought.tool_args)
        messages.append(result)
    else:
        return thought.final_answer
```

### 1.2 关键能力：Function Calling / Tool Use

要让模型能调用工具，模型本身需要支持 **Function Calling**（函数调用），也就是你告诉模型有哪些工具可用，模型会输出一个结构化的“我想调用这个工具，参数是这些”。

目前国内可用的本地模型，例如 DeepSeek、Qwen、GLM 等，很多都支持 Function Calling。这也是你公司内网可以构建 Agent 的基础。

### 1.3 你怎么使用 Agent？

你现在用 Cline + DeepSeek API 开发项目，这其实就是一个 Agent：Cline 内部会调用模型，模型决定是读文件、写文件、执行命令还是搜索网页。

**对普通开发者来说，使用 Agent 有三个层次：**

1. **直接用现成的 Agent 产品**
   - 比如 Cline、OpenCode、Aider、AutoGPT 等。
   - 你只需描述任务，它们内部完成工具调用循环。
2. **用框架自己搭 Agent**
   - 比如 LangChain、LlamaIndex、Semantic Kernel，或者更轻量的自研。
   - 你定义工具、设置系统提示词、控制循环。
3. **从零手写 Agent**
   - 直接调用模型 API，自己实现循环、工具管理、记忆、错误处理。
   - 这是理解最深的方式，也最适合你现在的学习目标。

**结合你的公司环境**：
你们内网只能本地部署大模型，没有 Agent 能力，说明你们现在只是“问答式调用”。但只要你本地模型支持 Function Calling，你完全可以自己写一个简单的 Agent，让它去操作你们内网的数据库、文件系统、API。
比如：写一个“文件管理助手”，你问“帮我找上周修改过的所有 PDF 并打包”，Agent 会调用查找文件、压缩文件等工具。

# 2. 什么是 Harness 技术？如何使用 Harness 技术？

### 2.1 本质理解

你给的 DeepSeek Harness（https://deepseek.com/harness/，[GitHub](https://github.com/deepseek-ai/deepseek-harness)）是 DeepSeek 开源的一套**模型训练与评测框架**，类似 OpenAI 的 `lm-evaluation-harness` 或 EleutherAI 的 `lm-eval-harness`。

在 LLM 领域，**Harness 通常指一个标准化的“测试/训练脚手架”**，让你能：

- 统一加载不同模型（本地权重或 API）
- 跑标准评测数据集（如 MMLU、C-Eval、HumanEval）
- 自定义评测任务
- 进行少样本/多样本推理
- 甚至支持微调、LoRA 等训练流程

简单说：**Harness 是模型质量的“体检工具”和“训练工具”**。

### 2.2 你为什么需要关注 Harness？

因为你的目标是“系统理解 AI 原理，能深入使用”，而且公司内网需要本地部署模型。你们未来一定会遇到一个问题：

> 这个本地模型到底行不行？它能不能用在我们的业务场景里？换一个模型会不会更好？

这时就不能只靠“感觉”，而要用 Harness 来**量化评估**。

### 2.3 如何使用 DeepSeek Harness？

虽然我无法访问你给的链接，但基于通用 LLM Harness 的设计，使用流程大致如下：

1. **安装**

   ```
   git clone https://github.com/deepseek-ai/deepseek-harness.git
   cd deepseek-harness
   pip install -e .
   ```
   
2. **准备模型**

   - 如果是 Hugging Face 模型，直接指定模型路径或名称。
   - 如果是你们内网部署的模型（比如通过 vLLM 或 Ollama），一般可以通过 OpenAI 兼容 API 接入。

3. **运行标准评测**

   bash

   ```
   python eval.py --model deepseek-7b --tasks mmlu,ceval,humaneval
   ```

4. **自定义评测任务**

   - 你可以定义一个 YAML 或 Python 文件，描述你的业务数据集。
   - 比如：把你们公司文件管理场景中的“文件分类准确率”“命名实体识别准确率”做成评测集，定期跑。

5. **接入训练/微调**

   - 一些 Harness 支持 LoRA 微调、量化等。
   - 你可以用它来对本地模型做垂直领域的微调，并用同一套评测来验证效果。

**给你的建议**：
先把这个 Harness 当作一个“黑盒工具”用起来，跑通几个标准评测，看看本地模型的表现。然后尝试自定义一个和你们业务相关的评测集（例如从文件标题中提取项目编号），这样你就真正理解了“评估模型”这件事。

# 3. 什么是 Claude Code、Codex？如何使用这些工具？

### 3.1 本质理解

**Claude Code** 是 Anthropic 推出的**终端里的 AI 编程 Agent**。

**Codex**（这里指 OpenAI Codex CLI / 云端 Codex）是 OpenAI 的同类工具。

它们和 Cline 的本质是一样的：

- 在终端或 IDE 中运行
- 能读取你的整个项目文件
- 能执行 shell 命令
- 能修改代码、运行测试、提交 git
- 你只需要用自然语言描述需求，它自己规划并执行

区别在于：

- **Claude Code** 背后是 Claude 模型，擅长代码理解、长上下文、工具调用。
- **Codex** 背后是 GPT 系列，某些场景下代码生成能力强。
- **Cline** 则是开源、可接任意模型（包括 DeepSeek）的类似工具。

### 3.2 你为什么要了解它们？

你目前使用的是 Cline + DeepSeek API，这已经是 AI Coding 的正确姿势。但了解 Claude Code 和 Codex 能让你：

- 理解不同工具的设计理念（比如 Claude Code 的“计划模式”、Codex 的“沙盒执行”）
- 知道什么时候该用哪个（比如 Claude Code 更适合长任务、Codex 更适合快速原型）
- 学习它们的**提示词策略和系统设计**，将来你可以自己写一个类似的工具

### 3.3 如何使用？

由于你依赖国内工具、网速慢、国外模型贵，**你不一定直接付费使用 Claude Code 或 Codex**，但你可以：

1. **看它们的官方文档和演示视频**，理解工作流。
2. **用开源替代品**：Cline、OpenCode、Aider、Continue 等，接 DeepSeek 或本地模型。
3. **模仿它们的交互方式**：在自己的 Cline 配置中，设置更详细的系统提示词，模仿 Claude Code 的“计划-执行-审查”模式。

**具体到你的 Django 文件管理系统**，你可以这样使用 Cline：

- 让它先读你的项目结构，生成一个开发计划。
- 让它实现“断点续传”功能，给出代码和测试。
- 让它写 API 文档和版本控制的逻辑。
- 你负责审查代码、运行测试、合并分支。

# 4. 什么是 Vibe Coding？什么又是 AI Coding？我们如何使用这些工具？

### 4.1 概念区分

- **AI Coding**：泛指一切用 AI 辅助编程的方式，包括代码补全、代码生成、代码解释、自动重构、测试生成等。
- **Vibe Coding**：是 AI Coding 的一种**风格/哲学**，由 Andrej Karpathy 带火。核心是：
  - 你不再逐行思考代码，而是描述“我想要什么感觉/效果”。
  - 让 AI 生成大部分代码。
  - 你主要通过“感觉”来判断结果对不对，不断用自然语言调整。
  - 适合快速原型、个人项目、探索性开发，不适合需要严谨工程的大型项目。

### 4.2 你怎么用？

你是一名 Python 开发者，**不能完全 Vibe Coding**，但可以“混合模式”：

1. **用 Vibe Coding 快速搭建原型**
   - 比如你的 Django 文件管理系统，先用 Cline 说：“帮我创建一个 Django 项目，支持文件上传、断点续传、API、版本控制，先给个最小可用版本。”
   - 它会生成大部分代码，你只需审查和运行。
2. **用传统工程思维做架构和关键模块**
   - 文件系统的并发、断点续传的完整性、版本控制的冲突处理，这些核心逻辑需要你亲自设计。
3. **让 AI 帮你写测试、文档、重构**
   - 这是 AI Coding 最擅长的部分，能大幅提高效率。

**实操建议**：
在你的 Django 项目中，先让 Cline 生成整体框架，然后你逐步填充业务逻辑，每完成一个功能就让它写单元测试。这样你既能快速推进，又能保证代码质量。

# 5. AI 时代如何使用这些强大的 AI 工具或技能？普通人如何使用？如何增强自己的能力边界和深度？

### 5.1 普通人的使用层次

我把普通人的 AI 使用分为四个层次，你可以对照自己定位：

| 层次               | 描述                                              | 典型工具                    |
| :----------------- | :------------------------------------------------ | :-------------------------- |
| **L1：使用者**     | 用现成 AI 产品问答、生成内容                      | ChatGPT、豆包、Kimi         |
| **L2：高级使用者** | 会写复杂 Prompt，会组合多个工具，能搭建简单工作流 | Coze、Dify、扣子            |
| **L3：构建者**     | 能调用 API 或本地模型，开发自己的 Agent / 应用    | LangChain、Cline、自研脚本  |
| **L4：深入研究者** | 理解模型原理、会微调、会评估、能优化部署          | Transformers、Harness、vLLM |

你现在处在 **L2 和 L3 之间**，目标是 **L4**。

### 5.2 如何增强能力边界？

**核心思想：把 AI 当成你的“外脑”和“自动化员工”，而不是一个聊天机器人。**

具体方法：

1. **用 AI 加速学习**
   - 遇到不懂的概念，直接问 AI 让它用你熟悉的 Python 例子解释。
   - 让 AI 帮你总结长文档、翻译英文论文。
2. **用 AI 自动化重复工作**
   - 你每天写的爬虫、数据分析脚本，可以让 AI 生成初稿，你修改。
   - 写周报、整理数据，用 AI 生成。
3. **用 AI 构建自己的工具**
   - 比如：写一个“自动分析日志并报警”的脚本，接入本地模型让它判断异常。
   - 你的 Django 文件管理系统就是一个很好的练手项目。
4. **用 AI 突破英文障碍**
   - 安装沉浸式翻译插件，阅读英文文档时边看边学。
   - 让 AI 把关键英文段落翻译成中文，同时保留原文对照。
   - 长期坚持，英文能力会自然提升。

### 5.3 针对你公司内网的限制

你们不能使用外部 API，只能本地部署大模型。这反而是一个**优势**，因为：

- 你能学到完整的本地部署、推理优化、RAG、Agent 构建等工程能力。
- 你可以用开源模型（DeepSeek、Qwen、GLM 等）在自己的机器或内网服务器上搭建完整 AI 栈。

**建议你利用内网环境做这些事：**

1. 用 **Ollama** 或 **vLLM** 在本地部署 DeepSeek-R1 或 Qwen。
2. 搭建 **Open WebUI** 或 **LobeChat**，作为内部问答界面。
3. 用 **Dify** 或 **FastGPT** 搭建内部知识库问答（RAG）。
4. 自己写一个 **Agent**，连接内网数据库和文件系统。
5. 用 **DeepSeek Harness** 评估这些模型在不同任务上的表现。

这样你不仅是在“用 AI”，而是在“构建 AI 系统”，这才是真正增强能力边界的方式。

# 6. 深度学习和使用 AI，学习路径有什么？如何能够深入地学习到 AI 相关技术、工具、技能？

### 6.1 总体学习路径（结合你的背景）

你已经有 Python 开发和数据分析基础，所以不需要从编程学起。我建议按以下五个阶段进行：

#### 阶段一：补齐 AI 基础概念（1—2 个月）

**目标**：理解 Transformer、LLM 的基本原理，能看懂模型架构和推理流程。

**学习内容**：

- 神经网络基础：感知机、反向传播、梯度下降（快速复习）
- Transformer 架构：注意力机制、位置编码、编码器-解码器
- 大模型训练范式：预训练、监督微调、RLHF、LoRA
- Token、Embedding、上下文长度、温度、Top-p 等概念
- 中文资源：李宏毅《机器学习》课程、Datawhale 开源学习、Hugging Face 中文课程
- 英文辅助：用沉浸式翻译读 `Attention Is All You Need` 论文、Hugging Face 文档

**实操**：

- 用 Python 从零实现一个简单的 Transformer 或 GPT（几百行代码）
- 用 Hugging Face Transformers 加载一个中文小模型（如 Qwen1.5-0.5B）跑推理

#### 阶段二：掌握推理与部署（1—2 个月）

**目标**：能在本地部署模型，并提供 API 服务。

**学习内容**：

- 推理优化：KV Cache、量化（GPTQ、AWQ、GGUF）、Flash Attention
- 部署工具：Ollama、vLLM、llama.cpp、Text Generation Inference
- 模型格式：safetensors、GGUF、ONNX
- API 设计：OpenAI 兼容接口、流式输出

**实操**：

- 在你的电脑或公司内网用 Ollama 部署 DeepSeek-R1 或 Qwen
- 用 vLLM 部署，并用 Python 调用 OpenAI 兼容 API
- 对比不同量化精度下的速度和显存占用

#### 阶段三：Prompt Engineering 与 RAG（1—2 个月）

**目标**：让模型能准确回答领域问题，并能调用外部知识。

**学习内容**：

- Prompt 技巧：Few-shot、Chain-of-Thought、ReAct、结构化输出
- Embedding 模型：BGE、M3E 等中文模型
- 向量数据库：Chroma、FAISS、Milvus
- RAG 流程：文档切分、检索、重排、生成
- 上下文工程：如何管理对话历史、如何做记忆

**实操**：

- 构建一个基于本地模型的企业文件管理 RAG 系统
- 用 Django + FAISS + 本地 Embedding 实现“上传 PDF 后可以语义搜索和问答”
- 优化 RAG 效果，比如调整切分策略、加入重排模型

#### 阶段四：Agent 开发与工具调用（2—3 个月）

**目标**：能构建自主 Agent，调用内部工具，完成复杂任务。

**学习内容**：

- Function Calling 原理与实现
- Agent 架构：ReAct、Plan-and-Execute、Reflexion
- 框架：LangChain / LlamaIndex / 自研
- 工具设计：如何把企业 API 封装成工具
- 记忆与状态管理

**实操**：

- 手写一个最小 Agent，不用框架，直接调用本地模型 API
- 为你的 Django 文件管理系统增加一个“文件助手 Agent”，能执行“查找文件”“打包下载”“生成文件摘要”等工具
- 加入多轮对话和错误恢复机制

#### 阶段五：模型评估与微调（2—3 个月）

**目标**：能评估模型能力，并能针对业务场景微调模型。

**学习内容**：

- 评测基准：MMLU、C-Eval、HumanEval、自定义评测
- DeepSeek Harness / lm-eval-harness 的使用
- 微调技术：LoRA、QLoRA、全参微调
- 数据构建：如何收集、清洗、标注领域数据
- 训练工具：Transformers Trainer、LLaMA-Factory、DeepSpeed

**实操**：

- 用 DeepSeek Harness 对你部署的本地模型做标准评测
- 构建一个小的业务数据集（如文件分类、元数据提取）
- 用 LLaMA-Factory 对模型做 LoRA 微调，并用 Harness 对比微调前后效果

#### 阶段六（可选）：多模态与前沿技术

**目标**：扩展能力边界，跟上最新进展。

**学习内容**：

- 多模态模型：视觉语言模型（Qwen-VL、InternVL）
- 语音模型：Whisper、Qwen-Audio
- 视频理解与生成：Sora 类模型、Runway
- MCP（Model Context Protocol）：连接 AI 与外部工具的标准协议

**实操**：

- 在你的文件管理系统中加入 OCR 或图像理解功能
- 用 MCP 让 Agent 连接更多外部工具

| 概念                                  | 一句话解释                                               | 为什么重要                                      |
| :------------------------------------ | :------------------------------------------------------- | :---------------------------------------------- |
| **RAG（检索增强生成）**               | 先从知识库检索相关内容，再让模型基于这些内容回答         | 解决模型知识过时、幻觉问题，企业应用核心        |
| **Function Calling / Tool Use**       | 模型能输出结构化指令去调用外部函数                       | Agent 的基础                                    |
| **MCP（Model Context Protocol）**     | 一个标准协议，让 AI 能连接各种外部工具和数据源           | 未来 Agent 生态的关键标准，类似“AI 的 USB 接口” |
| **Embedding / 向量数据库**            | 将文本转成向量，进行语义搜索                             | RAG 和语义检索的基础                            |
| **Context Engineering（上下文工程）** | 管理给模型的上下文，包括提示词、检索内容、工具结果、记忆 | 决定 Agent 效果的关键，比单纯 Prompt 更重要     |
| **Fine-tuning（微调）**               | 在预训练模型上，用领域数据继续训练                       | 让模型适应特定业务场景                          |
| **LoRA / QLoRA**                      | 低秩适配，一种高效微调方法                               | 资源有限时微调大模型的主流方法                  |
| **Quantization（量化）**              | 降低模型权重精度，减少显存占用                           | 本地部署大模型必备                              |
| **Evaluation（评估）**                | 用标准数据集或自定义数据集衡量模型能力                   | 判断模型好坏、比较不同模型的基础                |
| **Orchestration（编排）**             | 把多个模型、工具、数据源组合成工作流                     | 构建复杂 AI 应用的核心                          |

- **MCP（Model Context Protocol）**：连接 AI 与外部工具的标准协议，可让 Agent 无缝接入更多工具

#### 学习内容与方法
- 先不用框架，手写一个最小 Agent 循环（伪代码在前文已给）。
- 为本地模型定义 Function Calling 格式，并测试模型能否输出正确的工具调用。
- 实现 3—5 个文件管理相关工具：  
  - `search_files(query)`  
  - `get_file_metadata(file_id)`  
  - `compress_files(file_ids)`  
  - `summarize_file(file_id)`  
  - `get_file_version_history(file_id)`  
- 设计系统提示词，让模型根据用户意图选择工具。
- 加入多轮对话和错误处理（例如工具超时、参数错误）。
- 了解 MCP 协议，尝试用 MCP 将外部工具接入 Agent。

#### 学习资源推荐
- LangChain 官方文档（中文社区教程很多）
- B 站搜“手写 Agent”“Function Calling 实战”
- 开源项目：Cline、OpenCode、Aider（可参考它们的 Agent 实现）
- MCP 官方文档（有中文介绍）

#### 工作流 / 工具
- 将 Agent 与工作流结合：用 Dify 的自定义工具节点集成 Agent，或用代码直接编排。
- 建立 Agent 执行日志，便于调试和优化。

#### 三个项目具体行动建议

**项目 A：Django 企业文件管理系统**
- 在 Django 中新增“文件助手 Agent”接口。
- 用户输入自然语言指令，Agent 自动规划并调用工具。
- 示例场景：“帮我找上周的销售报告并打包下载”“总结最近三天上传的文件”。
- 记录 Agent 的执行过程（思考、工具调用、结果），方便调试。

**项目 B：智能数据分析与可视化平台**
- 实现“数据分析 Agent”：能够理解用户需求，选择合适的数据集，自动生成分析代码，执行并返回图表和结论。
- 为 Agent 添加“查询数据库结构”“执行 SQL/Pandas 代码”“生成报告”等工具。

**项目 C：个人知识库与自动化助手**
- 实现“个人助理 Agent”：能定时检查知识库更新、总结新文章、发送摘要到指定渠道（如邮件/微信/Telegram）。
- 为该 Agent 定义工具：搜索知识库、获取文章详情、生成摘要、发送通知。

#### 产出 / 里程碑
- 项目 A 拥有可用的文件助手 Agent，能完成“查找—总结—打包”等组合任务。
- 项目 B 具备自动分析数据并生成报告的能力。
- 项目 C 成为主动推送信息的自动化助手。
- 手写 Agent 核心代码（不依赖 LangChain 等重框架）。
- 一份 Agent 架构设计文档。

### 📘 阶段五：模型评估与微调（2—3 个月）

#### 阶段目标
- 能科学评估模型能力，并能针对业务场景微调模型。
- 掌握 DeepSeek Harness 等评测工具，理解 LoRA 微调流程。
- 学会用业务数据提升模型在特定任务上的表现。

#### 核心学习概念
- **Evaluation（评估）**：评测基准、自定义评测集  
- 评测基准：MMLU、C-Eval、HumanEval  
- DeepSeek Harness / lm-eval-harness 的使用  
- **Fine-tuning（微调）**：全参微调、**LoRA/QLoRA**  
- 数据构建：收集、清洗、标注领域数据  
- 训练工具：Transformers Trainer、LLaMA-Factory、DeepSpeed  
- 评估指标：准确率、F1、困惑度、ROUGE

#### 学习内容与方法
- 用 DeepSeek Harness 对本地部署的模型跑标准评测（MMLU、C-Eval 等）。
- 构建一个与文件管理业务相关的自定义评测集（例如：从文件标题提取项目编号、文件分类）。
- 用 LLaMA-Factory 对模型进行 LoRA 微调（需要一个小的业务数据集，几百条即可）。
- 微调前后用 Harness 或自定义脚本对比效果。
- 学习如何将微调后的模型部署回内网。

#### 学习资源推荐
- DeepSeek Harness GitHub（https://github.com/deepseek-ai/deepseek-harness）
- LLaMA-Factory 官方文档（有中文界面）
- B 站搜“LoRA 微调”“LLaMA-Factory 教程”
- Datawhale 的 LLM 微调实战课程

#### 工作流 / 工具
- 建立模型评估流水线：数据准备 → 评测 → 记录结果 → 微调 → 再评测。
- 使用 Dify 或自定义脚本管理不同模型版本的部署和切换。

#### 三个项目具体行动建议

**项目 A：Django 企业文件管理系统**
- 在系统中增加“模型评估”管理页面（可选，展示评测结果）。
- 将微调后的模型替换到 RAG 或 Agent 链路中，验证业务效果。
- 记录微调前后在自定义评测集上的分数变化。

**项目 B：智能数据分析与可视化平台**
- 构建一个“数据分析代码生成质量”评测集：给定自然语言问题，评估模型生成的 Pandas 代码正确率。
- 用该评测集评估并微调本地模型，提升自动分析准确度。

**项目 C：个人知识库与自动化助手**
- 构建“文章分类/摘要质量”评测集，评估模型在知识库场景下的表现。
- 微调模型以更好完成个人知识库中的标签提取和摘要生成。

#### 产出 / 里程碑
- 一份标准评测报告（本地模型 vs 微调模型）。
- 至少一个针对特定场景微调过的 LoRA 模型。
- 可复用的自定义评测脚本。
- 三个项目均验证了微调模型的业务效果。
