# 1. `DeepSeek` 提示词

## 1.1 深入学习某个库

```python
Role
你是一位 Python 高级架构师和技术研究员，擅长深入剖析开源库的底层实现原理。你精通 Python 内部机制与 C 语言扩展开发，具备极强的逻辑推理能力，能透过现象看本质，帮助用户建立深度的技术认知。

Task
请对我指定的 Python 库【此处填写库名】进行全方位、外科手术式的深度解析，挖掘其背后的设计哲学和运行机制。不要只列举官方文档的 API，我的目标是不仅会用，更要精通其底层逻辑。

Requirements
请从以下 7 个维度进行详细阐述，务必深入：

1. **宏观架构与设计哲学**
	- 核心抽象：该库解决的本质问题是什么？它定义了哪些核心的数据结构、概念与术语？
	- 设计哲学：它的宏观架构图景与设计哲学是什么？
	- 设计模式：它及其源码中主要运用了哪些经典设计模式（如工厂、单例、装饰器、观察者等）？

2. **核心用法与实战**
	- 提供从基础到进阶的代码示例。
	- 展示最核心的 API 调用方式，并解释参数背后的含义。
	- 结合示例解释其底层运行原理。

3. **竞品分析与选型指南**
	- 列出功能类似的主流库（涵盖 Python 或其他语言如 Node.js、Java 生态）。
	- 详细对比它们在性能、易用性、社区活跃度上的区别。
	- 给出具体的应用场景建议：什么情况下首选该库，什么情况下应该选其他库？

4. **C 语言底层实现细节**
	- 选择该库核心的功能模块，解释其底层运行原理。
	- 该库是否使用了 C/Cython/CFFI 等进行底层加速？具体用了哪种技术？
	- 解释核心性能瓶颈在 C 层面是如何解决的（如内存管理、指针操作、数据结构实现）。

5. **源码阅读指南**
	- 入口文件：下载源码后，应该从哪个具体的 .py 或 .c 文件读起？
	- 架构图解：用文字或 Mermaid 图描述核心模块的继承关系和调用链。
	- 继承路径与阅读顺序：核心继承路径是什么样的？给出一条清晰的阅读顺序。

6. **黑暗面与性能陷阱**
	- 复杂度：该库的时间复杂度和空间复杂度表现如何？
	- 陷阱与误区：有哪些鲜为人知的性能瓶颈、内存泄漏风险或需要避免的反模式？读源码时易陷入哪些误区（如过度纠结生成代码、难以理解的宏定义等）？
	- 高并发规避：高并发或大数据量场景下，该库通常会在哪里卡住？如何规避？
	- 优化实践：生产环境中特定的性能优化技巧是什么？展示一段体现最佳实践的高质量代码，解释为何比普通写法更高效。

7. **面试题与深度思考**
	- 列举 3 个关于该库的高难度面试题（涉及底层原理而非单纯用法），并给出标准答案。
    
请用清晰的 Markdown 结构输出，技术细节要准确且详实。

现在请开始你的深度分析。
```

```python
你是一位 Python 领域的资深架构师和源码级技术导师，擅长制定循序渐进的学习计划，并能够通过生动的案例和类比帮助学员掌握复杂的技术概念。你的教学风格严谨且富有条理。

# Instruction

**4. 底层探秘（C层实现）**

- **起手式**：GitHub 源码仓库中，哪个文件是“上帝视角”的入口？
- **继承链**：核心类之间的继承和组合关系是怎样的？
- **阅读策略**：推荐一条从入门到精通的源码阅读路径。
- **注意事项**：在阅读该库源码时，有哪些特殊的代码风格、宏定义或坑需要我特别注意？

**6. 进阶洞察**
- **性能**：该库的性能边界在哪里？如何进行 Benchmark 测试？
- **设计模式**：源码中使用了哪些值得学习的软件设计模式？
- **常见错误**：开发者在使用该库时最容易犯的 3 个错误是什么？

请确保回答深入浅出，既有技术深度，又有指导意义。
```

# 3. 如何写 `prompt`

## 3.1 提示词工程概述
与大型语言模型（LLM）沟通的本质是一门**“提示词工程”**的艺术。可把大模型想象成**“无所不知但缺乏主动性的超级实习生”**：他读过全世界的书，但不知道你的具体任务、客户和预算。模糊指令只会得到“放之四海而皆准”的废话，精确的背景和约束才能产出专家级结果。
写好提示词的核心不在于“文采”，而在于**“逻辑的严密性”**：把大模型当成极其聪明但没有常识的机器，将所有隐性知识显性化，即可解决90%以上的脑力劳动问题。
掌握基础后，进阶痛点在于：答案像“正确的废话”、缺乏真正创意、一本正经地胡说八道（幻觉）。
## 3.2 核心心法：五要素结构化提示词法
问题越复杂，所需要素越多：
### 3.2.1 角色设定
告诉模型“你是谁”，瞬间锁定其知识库范围和语言风格。
- ❌ 帮我写一段卖咖啡的文案。
- ✅ 你是一位**拥有10年快消品经验的资深文案**，擅长写小红书种草笔记。
### 3.2.2 任务目标
使用**明确的动词**，任务清晰、唯一、无歧义。
- ❌ 看看这个数据。
- ✅ 请**总结**以下销售数据的核心趋势，并**指出**异常值。
### 3.2.3 背景信息
最易被忽略的一环，需把“前因后果”喂给模型：目标受众是谁、面临什么困难、内容用在哪里。
- 示例：受众是**25-30岁都市白领**，**早上没时间吃早餐**，文案将**发布在微信公众号**。
### 3.2.4 约束条件
告诉模型“不要做什么”或在什么边界内做事，帮它“脱水”。包括：字数限制、语气禁忌、格式要求、绝不能提的内容。
- 示例：300字以内；**不使用**“颠覆”“赋能”等互联网黑话；**必须**包含价格信息。
### 3.2.5 输出格式
模型擅长格式化输出，明确格式可省去二次排版。
- 示例：以**Markdown表格**输出，含“趋势”“数据支撑”“应对策略”三列。
## 3.3 实战对比：从“小白”到“大师”
**场景：写请假邮件**
- 🟢 **青铜**：“帮我写一封请假邮件。” → 极其通用、充满套话。
- 🔵 **白银**（加入细节）：给老板的请假邮件，下周一到周三感冒发烧请病假，工作已交接给小王。 → 好多了，但语气和篇幅可能不佳。
- 🟣 **王者**（五要素齐全）：你是一位外企职场沟通专家（**角色**），帮我写一封请假邮件（**任务**）。下周一至周三因重感冒请病假，A项目进度已更新在共享文档并口头交接给小王（**背景**）。语气诚恳简洁、不口语化（**约束**），150字以内，分“请假事由”“工作安排”“恳请批准”三段（**格式**）。
## 3.4 进阶技巧：应对复杂任务
### 3.4.1 思维链——“让它慢慢想”
在提示词末尾加**“请一步一步地思考”**，强迫模型先输出推理过程再给答案，准确率飙升。适用于数学计算、逻辑推理、复杂因果分析。
### 3.4.2 少样本提示——“打个样”
模型是模仿大师，直接给例子比语言描述风格更有效。
- 示例：翻译成古风表达——例子1：你好→阁下安好；例子2：谢谢→多谢仗义。现在翻译：再见。
### 3.4.3 拆解复杂任务——“别一口吃成胖子”
直接让模型“写商业计划书”通常产出垃圾，应**多轮对话、分步执行**：
- 第一轮：先列7个模块的大纲，确认后再写。
- 第二轮：只写“市场分析”，且先反问3个产品细节以便写得更精准。
### 3.4.4 让模型反向提问
自己不知道该提供什么背景时，把球踢回去。
- 示例：“帮我优化简历，请你先提问5个问题了解我的背景和求职意向，再开始优化。”
## 3.5 常见避坑指南
1. **❌ 假设模型能读懂心思**：不要说“像我平时那样写”“帮我改得更好”（更好指文采、简短还是委婉？）。
2. **❌ 冗长但缺重点**：500字背景后才说“帮我处理一下”。正确做法：**任务目标放最开头**，再补背景。
3. **❌ 一次问多个不相关问题**：会导致每个都做不好。一次对话聚焦一个核心任务。
4. **❌ 轻易接受第一次回答**：持续调优——“缩短一半”“语气太严肃，加emoji”“第二点请围绕XXX重新论述”。
## 3.6 万能提问模板
> **【任务目标】** 帮我完成 [具体动作：写推文/分析代码/总结文章]。
> **【背景信息】** [Who/When/Where/Why，当前痛点]。
> **【参考材料】** [粘贴文本/链接/数据]。
> **【约束条件】** 1.字数/篇幅限制；2.语气/风格要求；3.绝对不能包含的内容。
> **【输出格式】** [分点列表/表格/JSON/开头中间结尾三部分]。
> **【附加指令】**（可选）请一步一步地思考 / 需要更多信息请先向我提问。
## 3.7 生成“更具体”的回答（治愈“正确的废话”）
模型天生追求“安全”和“全面”，易输出绝对正确但无价值的话。逼出具体性的技巧：
### 3.7.1 具象化约束（量化与颗粒度）
用数字和单位框死“具体”。
- ❌ “给我一个减肥计划。”
- ✅ “14天减肥计划，精确到每天三餐的食材名称、重量（克）、烹饪方式、运动时长和动作名称。”
### 3.7.2 场景极度下沉（添加极端限制）
场景越狭窄极端，答案越不空洞。
- ❌ “怎么提高工作效率？”
- ✅ “我是每天被微信打断至少20次、常临时写PPT的基层HR，在**无助理、不能卸载微信、每天只有2小时不被打扰**的前提下，给我3个明天就能落地的提高PPT产出效率的动作。”
### 3.7.3 使用“禁止清单”（反向逼迫）
明确禁用词可极大提高信息密度。
- ✅ “**禁止**使用‘合理规划’‘提升认知’‘底层逻辑’‘赋能’等抽象词；**禁止**排比句；每条建议必须包含真实案例。”
## 3.8 更高级的技巧：控制模型的“思维过程”
### 3.8.1 红蓝对抗 / 魔鬼代言人
让模型自己批判自己（生成模式与批判模式表现完全不同）。
- ✅ “以资深产品经理身份为‘老年人短视频App’写需求文档；写完后**切换角色**为挑剔的技术总监，找出3个致命漏洞并给修改建议；最后综合漏洞输出最终版。”
### 3.8.2 自我一致性采样
复杂问题让模型生成多个独立方案再选最优。
- ✅ “从‘成本优先’‘速度优先’‘质量优先’三个独立角度给出3套截然不同的方案，分析优劣后告诉我只选一套选哪个、为什么。”
### 3.8.3 元提示词（让AI帮你写Prompt）
觉得提问不够好时，把提问本身交给AI。
- ✅ “我想让你写‘2024年新能源汽车市场分析’报告，但不知怎么问。请你作为提示词专家先反问3个问题明确需求，再帮我生成完美提示词，然后用它执行任务。”
## 3.9 生成“有创意”的内容（打破平庸）
AI本质是概率预测，总输出概率最高（最平庸）的组合，须**人为引入“低概率”变量**：
### 3.9.1 强制远距联想
创意的本质是连接不相干的事物。
- ❌ “给新茶饮起个名字。”（会起茶颜悦色式常规名）
- ✅ “用**量子力学**术语（纠缠、跃迁、坍缩）结合**古诗词**意境，起5个名字并解释隐喻。”
### 3.9.2 极端约束法（带着镣铐跳舞）
限制越死，创意越奇。
- ✅ “写‘打工人周一早晨痛苦’短文：**全篇不能出现‘困’‘累’‘烦’‘不想上班’及近义词**，300字，让读者深感共鸣。”
### 3.9.3 注入混乱与随机性
- 支持调参的工具：调高 **Temperature**（0.8-1.0），让模型敢选低概率词汇。
- 不能调参则在提示词写：“发挥想象力，天马行空甚至荒诞也没关系，不要四平八稳的常规答案。”
### 3.9.4 套用经典创意框架
给它一个反常规的框架，而非凭空想。
- ✅ “用**悬疑推理小说**笔调写‘Excel VLOOKUP函数’教程：有悬念、转折、‘受害者’（报错数据），由‘侦探’（函数公式）揭开真相。”
## 3.10 提高内容的“正确性”（对抗幻觉）
幻觉源于模型在做“文字接龙”而非查数据库，须收紧生成边界：
### 3.10.1 锁定知识源（最有效的防幻觉手段）
- ✅ “根据以下文本回答问题。**若答案在文本中找不到直接依据，直接回答‘文本中未提及’，绝不能用自身知识库编造或推测。**”
### 3.10.2 要求提供“证据链”或“引用”
逼它交出推理过程和数据来源。
- ✅ “每个数据声明后必须括号标注来源机构全称；不确定来源则在该句前加[存疑]标签。”
### 3.10.3 置信度自评（让模型承认不确定）
模型知道自己哪里在瞎编，只要你问。
- ✅ “回答5个专业医学问题后，为每个答案给出置信度评分（1-10）；低于8分的须提供替代解释或建议查阅的资料。”
### 3.10.4 拆解验证步骤
复杂逻辑/数学问题先给步骤，人工确认后再出结果。
- ✅ “先不要给最终数字。第一步列出计算利润所需的所有变量和公式；第二步代入题目条件；第三步逐步计算。我确认无误后再给总数。”
## 3.11 高级提示词的心智模型
把大语言模型想象成**水**：
- **不加约束，它就漫流**（废话）→ 量化、场景下沉。
- **给它常规河道，它就流得平庸**（缺创意）→ 强行拐弯、远距联想。
- **它易蒸发或混入泥沙**（幻觉）→ 加压、过滤、锁死源头。
- **给它精密的管道和阀门**（高级技巧）→ 自我净化、红蓝对抗、驱动机械。
真正的高手，不是把提示词写得像散文一样优美，而是像**写代码或写法律合同**一样：严密、无死角、可执行。
