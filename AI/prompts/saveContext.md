请实现一个纯本地运行的浏览器扩展，用于将 DeepSeek 网页版当前对话保存为 Markdown 笔记，防止因上下文限制丢失对话内容。扩展需支持 Chrome、Edge 和 Firefox，使用 WebExtension Manifest V3 跨浏览器标准 API，不依赖任何远程服务或后端。

# 1. markdown 展示

## 一、核心功能需求

1. **手动保存当前对话**
   - 用户点击工具栏图标打开扩展弹窗（popup），自动检测当前标签页是否为 DeepSeek 对话页面（URL 匹配 `chat.deepseek.com` 或未来可能的变体）。
   - 如果是对话页面，弹窗内显示：
     - 当前对话标题（从页面获取）
     - 消息数量（用户/助手轮次）
     - 预计保存体积（字符数或估算 KB）
     - 是否已存在该对话的笔记（若存在，显示“将更新已有笔记”）
   - 用户点击“保存”按钮后，扩展抓取当前对话完整内容，转换为 Markdown，存入本地笔记库（IndexedDB）。
   - 若同一对话已存在笔记（通过对话唯一标识判断，优先使用 URL 中的会话 ID，其次用对话标题+首次保存时间），则覆盖更新该笔记内容，保持原文件名不变（除非用户重命名），并在弹窗提示“已更新”。
   - 首次保存的笔记命名格式：`对话标题_YYYY-MM-DD_HH-mm-ss.md`（保存时的本地时间，时:分:秒使用短横线避免文件名非法字符）。对话标题需清理文件系统非法字符（如 `\/:*?"<>|` 替换为下划线）。
2. **本地笔记库管理**
   - 存储于浏览器 IndexedDB，数据结构包含：`id`（唯一标识）、`conversationId`（对话标识）、`title`、`createdAt`、`updatedAt`、`content`（Markdown 文本）、`fileName`。
   - 扩展选项页（或独立管理页面）提供：
     - **历史笔记列表**：按更新时间倒序显示，支持分页或滚动加载。
     - **搜索**：按标题或内容关键词过滤。
     - **重命名**：修改笔记标题（同步更新 `fileName` 和 Markdown 一级标题）。
     - **删除**：单个删除或批量删除，需二次确认。
     - **导出全部**：一键将所有笔记导出为一个 `.zip` 文件（内含全部 `.md` 文件）和一个 `.json` 文件（包含所有笔记元数据与内容）。使用 JSZip 或类似纯前端库生成压缩包（需在扩展内打包，避免 CDN 依赖）。同时支持单独导出某个笔记为 `.md` 下载。
   - 笔记数据仅存储在本地，不上传任何服务器。
3. **续接提示词与恢复上下文**
   - 在每个笔记的查看/编辑界面提供“复制续接提示词”按钮，点击后弹出选项：
     - **完整历史**：复制完整 Markdown 内容到剪贴板，并在开头添加提示语：`以下是之前对话的完整记录，请基于此继续回答我的新问题：\n\n---\n\n`。
     - **最近 N 轮**：用户可输入轮次数（默认最近 5 轮），插件提取对应数量的用户/助手消息，生成同样的提示语格式。
     - **生成摘要**：使用本地规则生成简洁摘要（见下文摘要算法），复制为提示语。
   - **长对话提醒**：当用户选择“完整历史”或“最近 N 轮”时，若复制内容超过约 10 万字符（可配置），弹窗提示“内容较长，可能超出新对话上下文限制，建议改用摘要或减少轮次”，但允许用户继续复制。
   - **摘要算法**（纯本地、简单抽取式）：
     - 提取每轮用户问题的完整文本（去掉代码块和多余空白）。
     - 对每轮助手回答，保留开头第一段（不超过 200 字）以及其中出现的列表项标题（以 `-`、`1.` 等开头的行），忽略代码块、公式、链接的详细内容。
     - 合并后生成 Markdown 格式摘要，并标注“（自动生成的摘要，可能不完整）”。
4. **快捷键与状态显示**
   - 注册扩展命令 `Ctrl+Shift+S`（Mac 为 `Command+Shift+S`）触发保存当前对话，无需打开弹窗，保存成功后通过浏览器通知或扩展图标角标显示“已保存”。
   - 扩展图标在检测到 DeepSeek 对话页面且未保存最新内容时显示一个绿色小圆点；已保存或非对话页面则无角标。
   - 弹窗内保存按钮旁显示上次保存时间和当前状态（“待保存”/“已保存”/“保存中…”）。

## 二、数据抓取策略（关键实现）

采用**网络响应拦截为主，DOM 解析回退**的混合方案，确保数据完整性和稳定性。

### 1. 网络响应拦截（首选）

- 在内容脚本（content script）中注入页面上下文脚本，劫持 `window.fetch` 和 `XMLHttpRequest`。
- 监听所有请求，筛选出包含对话数据的接口响应（识别特征：URL 包含 `/chat`、`/conversation`、`/message` 等关键词，或响应体为包含 `messages` 数组的 JSON）。
- 由于 DeepSeek 可能使用流式响应（SSE 或 WebSocket），需要：
  - 对 `fetch` 的 `response.body` 读取流，拼接完整内容后再解析。
  - 对 WebSocket，需 hook `WebSocket` 构造函数，监听 `message` 事件，累积数据帧，识别对话结束标志（如 `[DONE]` 或流结束）。
- 解析响应体，提取标准化的消息列表（用户、助手、可能包含的思考过程、代码块、引用链接等）。
- 将解析结果暂存在扩展的 `sessionStorage` 或通过 `chrome.runtime.sendMessage` 发送给后台/弹窗。
- **容错**：若连续 3 次无法拦截到结构化数据，或页面加载 30 秒内未检测到相关请求，则自动回退到 DOM 解析。

### 2. DOM 解析回退

- 在 content script 中直接查询页面 DOM 元素，提取对话容器内的消息节点。
- 使用多种选择器策略：优先按 `[class*="message"]`、`[data-testid*="message"]`、`[class*="chat"]` 等通用模式匹配，再针对 DeepSeek 已知的类名（需在实现时调研）。要求选择器可配置，便于后续维护。
- 提取每条消息的：
  - 角色（通过头像、类名、位置判断是用户还是助手）
  - 正文内容（保留内部 HTML 结构，用于后续转换为 Markdown）
  - 思考过程（如果页面有折叠的“思考”区块，展开并提取）
  - 代码块、表格、公式、链接等元素保持原样。
- 将 DOM 提取结果转换为与网络拦截相同的数据结构。

### 3. 数据模型

- 统一的数据结构为：

  ```json
  {
    "conversationId": "从URL或接口获取的唯一ID",
    "title": "对话标题",
    "messages": [
      {
        "role": "user/assistant",
        "content": "用户问题或助手回答的原始文本/HTML",
        "thinking": "思考过程（可选）",
        "attachments": ["链接或引用信息（可选）"]
      }
    ]
  }
  ```

## 三、Markdown 格式规范

- 每条笔记的 Markdown 结构如下：

  ```markdown
  # [对话标题]
  
  > 保存时间：YYYY-MM-DD HH:mm:ss  
  > 原始链接：[对话URL]（如果可获取）
  
  ## 用户
  [用户问题内容，保留原有格式，代码块、公式等用 Markdown 语法表示]
  
  ## 助手
  [助手回答内容，保留 Markdown 格式，包括代码块、表格、公式、链接等]
  
  > 思考过程（如果有）：
  > [思考内容，用引用块包裹]
  ```

- 每条用户/助手消息之间空一行，消息按时间顺序排列。

- 如果同一轮有多条消息（如助手连续回答），分别用 `## 助手` 继续。

- 公式需转换为 LaTeX 语法（用 `$...$` 或 `$$...$$` 包裹），如果无法转换，保留原文。

- 代码块使用三反引号，标明语言（如果能识别）。

- 链接保留原始 URL 和链接文本。

- 图片：由于内容可能包含图片，若为外链，直接使用 `![描述](URL)`；若为内嵌 base64，不保存图片数据，仅记录占位符 `[图片]`，并提示用户手动处理。

## 四、UI/UX 设计

- **弹窗（Popup）**：尺寸约 400x500px，简洁布局。
  - 顶部显示当前页面状态（是否对话页面、对话标题）。
  - 中间显示消息数量、预计大小、已存笔记状态。
  - 底部按钮：`保存`、`打开笔记库`、`设置`。
- **笔记库页面**：在扩展弹出的独立标签页中实现（通过 `chrome.tabs.create` 打开扩展内页面），包含搜索框、笔记列表、操作按钮（打开、导出、重命名、删除、复制续接提示词）。
- **设置选项页**：配置快捷键、默认复制模式（完整/最近N轮/摘要）、长对话提醒阈值、是否开启网络拦截等。
- 所有界面使用纯 HTML/CSS/JS，不依赖外部 UI 框架，确保跨浏览器兼容。可使用系统字体。

## 五、权限与浏览器兼容性

- **Manifest V3** 权限申请：
  - `storage`：存储笔记数据和设置。
  - `activeTab`：获取当前标签页信息。
  - `scripting`：注入内容脚本。
  - `tabs`：打开笔记库页面。
  - `clipboardWrite`：复制续接提示词。
  - `downloads`：导出文件。
  - `notifications`：保存成功通知（可选，若不用通知可去掉）。
  - `webRequest` / `declarativeNetRequest`：如果采用网络拦截需要（但 MV3 中不能读取响应体，所以实际不依赖此权限，网络拦截通过内容脚本 hook 实现，因此**无需申请 webRequest 权限**）。
  - `host_permissions`：`https://chat.deepseek.com/*`（仅针对 DeepSeek 域）。
- **不使用** `chrome.*` 专有 API，全部使用 `browser.*` 或通过 `webextension-polyfill` 兼容。在 background script 中统一使用 `browser` 命名空间。
- 需在 Chrome、Edge、Firefox 上测试通过，特别注意 Firefox 对 `browser` 对象的原生支持以及 IndexedDB 行为一致性。

## 六、错误处理与边界情况

- 非 DeepSeek 对话页面：弹窗提示“请在 DeepSeek 对话页面使用此扩展”。
- 抓取失败：弹窗显示错误信息，并提供“重试”按钮；若网络拦截失败自动回退 DOM，若 DOM 也失败则提示用户手动复制粘贴。
- 对话标题为空：使用“未命名对话_日期”作为默认标题。
- 文件名冲突：如果同名文件已存在（理论上不会，因为包含秒级时间），自动添加序号 `(1)`、`(2)`。
- 存储空间不足：捕获 IndexedDB 错误，提示用户删除部分笔记或导出后清理。
- 内容包含特殊字符：进行必要的转义，确保 Markdown 正确渲染。
- 更新笔记时发现原笔记被删除：按首次保存流程创建新笔记。
- 保存过程中用户关闭弹窗：使用 `chrome.runtime` 消息保证后台继续完成保存。

## 七、交付要求

- 提供完整扩展源码，包含：
  - `manifest.json`（支持 Chrome/Edge/Firefox 的 MV3）
  - background service worker
  - content script（含注入脚本）
  - popup HTML/CSS/JS
  - 笔记库页面和设置页面
  - 工具函数库（Markdown 转换、文件命名清理、摘要算法等）
  - 使用 JSZip 处理导出压缩
- 代码需有清晰注释，说明关键逻辑和易变部分（如 DOM 选择器）。
- 提供简单的开发文档，说明如何加载到各浏览器进行测试，以及未来如何调整网络拦截规则或 DOM 选择器。
- 确保所有功能在最新版 Chrome、Edge、Firefox 上测试通过，无跨浏览器兼容性错误。

## 八、附加说明

- 插件所有数据仅保存在用户本地浏览器中，不进行任何网络上传。
- 网络拦截实现时要避免干扰页面原有请求，只读取不修改。
- 注意隐私：扩展只处理 DeepSeek 域的数据，不访问其他网站。
- 若后续 DeepSeek 网页版改版导致抓取失效，应能通过更新选择器或拦截规则快速修复，因此代码中相关部分需模块化、可配置。

  - 思考过程（如果页面有折叠的“思考”区块，展开并提取）
  - 代码块、表格、公式、链接等元素保持原样。
- 将 DOM 提取结果转换为与网络拦截相同的数据结构。

### 3. 数据模型

- 统一的数据结构为：

  ```json
  {
    "conversationId": "从URL或接口获取的唯一ID",
    "title": "对话标题",
    "messages": [
      {
        "role": "user/assistant",
        "content": "用户问题或助手回答的原始文本/HTML",
        "thinking": "思考过程（可选）",
        "attachments": ["链接或引用信息（可选）"]
      }
    ]
  }
  ```

## 三、Markdown 格式规范

- 每条笔记的 Markdown 结构如下：

  ```markdown
  # [对话标题]
  
  > 保存时间：YYYY-MM-DD HH:mm:ss  
  > 原始链接：[对话URL]（如果可获取）
  
  ## 用户
  [用户问题内容，保留原有格式，代码块、公式等用 Markdown 语法表示]
  
  ## 助手
  [助手回答内容，保留 Markdown 格式，包括代码块、表格、公式、链接等]
  
  > 思考过程（如果有）：
  > [思考内容，用引用块包裹]
  ```

- 每条用户/助手消息之间空一行，消息按时间顺序排列。
- 如果同一轮有多条消息（如助手连续回答），分别用 `## 助手` 继续。
- 公式需转换为 LaTeX 语法（用 `$...$` 或 `$$...$$` 包裹），如果无法转换，保留原文。
- 代码块使用三反引号，标明语言（如果能识别）。
- 链接保留原始 URL 和链接文本。
- 图片：由于内容可能包含图片，若为外链，直接使用 `![描述](URL)`；若为内嵌 base64，不保存图片数据，仅记录占位符 `[图片]`，并提示用户手动处理。

## 四、UI/UX 设计

- **弹窗（Popup）**：尺寸约 400x500px，简洁布局。
  - 顶部显示当前页面状态（是否对话页面、对话标题）。
  - 中间显示消息数量、预计大小、已存笔记状态。
  - 底部按钮：`保存`、`打开笔记库`、`设置`。
- **笔记库页面**：在扩展弹出的独立标签页中实现（通过 `chrome.tabs.create` 打开扩展内页面），包含搜索框、笔记列表、操作按钮（打开、导出、重命名、删除、复制续接提示词）。
- **设置选项页**：配置快捷键、默认复制模式（完整/最近N轮/摘要）、长对话提醒阈值、是否开启网络拦截等。
- 所有界面使用纯 HTML/CSS/JS，不依赖外部 UI 框架，确保跨浏览器兼容。可使用系统字体。

## 五、权限与浏览器兼容性

- **Manifest V3** 权限申请：
  - `storage`：存储笔记数据和设置。
  - `activeTab`：获取当前标签页信息。
  - `scripting`：注入内容脚本。
  - `tabs`：打开笔记库页面。
  - `clipboardWrite`：复制续接提示词。
  - `downloads`：导出文件。
  - `notifications`：保存成功通知（可选，若不用通知可去掉）。
  - `webRequest` / `declarativeNetRequest`：如果采用网络拦截需要（但 MV3 中不能读取响应体，所以实际不依赖此权限，网络拦截通过内容脚本 hook 实现，因此**无需申请 webRequest 权限**）。
  - `host_permissions`：`https://chat.deepseek.com/*`（仅针对 DeepSeek 域）。
- **不使用** `chrome.*` 专有 API，全部使用 `browser.*` 或通过 `webextension-polyfill` 兼容。在 background script 中统一使用 `browser` 命名空间。
- 需在 Chrome、Edge、Firefox 上测试通过，特别注意 Firefox 对 `browser` 对象的原生支持以及 IndexedDB 行为一致性。

## 六、错误处理与边界情况

- 非 DeepSeek 对话页面：弹窗提示“请在 DeepSeek 对话页面使用此扩展”。
- 抓取失败：弹窗显示错误信息，并提供“重试”按钮；若网络拦截失败自动回退 DOM，若 DOM 也失败则提示用户手动复制粘贴。
- 对话标题为空：使用“未命名对话_日期”作为默认标题。
- 文件名冲突：如果同名文件已存在（理论上不会，因为包含秒级时间），自动添加序号 `(1)`、`(2)`。
- 存储空间不足：捕获 IndexedDB 错误，提示用户删除部分笔记或导出后清理。
- 内容包含特殊字符：进行必要的转义，确保 Markdown 正确渲染。
- 更新笔记时发现原笔记被删除：按首次保存流程创建新笔记。
- 保存过程中用户关闭弹窗：使用 `chrome.runtime` 消息保证后台继续完成保存。
